# Getting to 1.0

What stands between 0.15 and a public 1.0, found while releasing 0.15.0. "Blocker" means do not publish without it.

## Blockers

| What | Why | Next step |
|---|---|---|
| **Back up the phone signing key** | The release key now exists and signs `assembleRelease`, but only one copy is on this PC (`~/.android-keys`). Lose it and nobody can update the app. | Copy that whole folder to a password manager's file storage or an encrypted drive. |
| **Licences** | See `THIRD_PARTY_NOTICES.md`: the Piper fallback voice is unclear, espeak-ng is GPL, the phone's wake-word model is not confirmed for redistribution, and the Gemma terms need a read. | Drop Piper, decide how espeak-ng is shipped, confirm the wake-word model, read the Gemma model card. |
| **Where the phone app is published** | Play Store needs a developer account, a privacy policy and a data-safety form; a plain APK on GitHub Releases does not. | Pick one. GitHub Releases first is the quick path. |
| **Setup is long** | Tailscale on two devices plus pairing is about five minutes for a technical person. | A clearer first-run flow; see "Later" below. |

## Done in 0.15.0 while testing the release

- The release build crashed at start (the shrinker was allowed to rewrite Kotlin itself). Fixed; the release build now starts and connects.
- Release checks failed on an old `fragment` library brought by biometric. A current one is pinned.
- The keyboard covered the message box on the main screen. Fixed.

## Still labelled experimental

- **Control app windows** (`computer_control`): slow, and it clicks and types for you. Keep it behind its switch and labelled for 1.0, or hold it back.
- **Offline helper**: typed requests only, simple things only (9 of 10 commands, 4 of 9 everyday questions right in our test). No voice input offline yet.

## Not tested yet

- The offline helper inside a *release* build (the debug hooks that measure it are off there). It was only checked in debug.
- A clean install on a second phone, and on a PC that has never had the app (the installer's self-test passes).
